## Implementation and historical compatibility

The authoritative reusable validator is `assertLevelRankDomain()` in Canonical `validation.ts`. It throws existing `CanonicalDomainError('DOMAIN_VALIDATION', ...)` with the field and permitted range.

All submitted structures pass this validator through `assertMutationShape()` before writes. Password-only mutations validate the persisted structure before changing password. A valid structure repair submitted with password is accepted. Invalid submissions return HTTP 422 through the existing error mapping, with no partial persistence or revision advance.

Review and each explicitly requested CONFIRMED transition use `assertBlockForConfirmation()`, which applies the current domain. Persisted confirmed-block revalidation uses the existing pre-contract invariants through `assertPersistedBlockValid()`; it does not apply the new range rule globally. This preserves already-confirmed historical structures during unrelated mutations without creating any durable compatibility flag.

Directly seeded historical Level 18, Level -6 and Rank 14 remain exact across reads and runtime reload. TEXT, CLASSIFICATION, RELATIONS and provenance-only mutations succeed and preserve structure and confirmation state. Password or new STRUCTURE intent requires repair. New Review, Confirm and reconfirm attempts reject invalid historical values.

Library controls now use native numeric Input controls with min 0 / max 12 or 13 / step 1. They retain directly typed out-of-range values on blur, visibly identify field/range, preserve blank as null and explicit zero as zero, and respect native keyboard/spinner bounds. Pure helpers validate local working state without normalization. Both Save entry and actual save execution gate STRUCTURE/password changes; unrelated TEXT-only edits omit structure and remain allowed. Hydration/adoption were not changed.

Carder production files and protocol were untouched. Its existing selective mutation reaches the same Canonical boundary. Tests exercise valid/invalid values and historical text-only/repair paths.

External `structure-result.ts` uses field-specific bounded predicates in both claimed-value validation and coherence checking. Generic nonnegative numeric validation for other fields is unchanged. Invalid candidates are INELIGIBLE with STRUCTURE_VALUE_INVALID and no eligible resulting structure; Apply re-evaluates and rejects. Candidate history/raw evidence and normalizer v2 remain unchanged.
