## 4. Evidence-backed diagnosis

At the baseline SHA, Workspace bridge projection currently maps Canonical NORMAL
Spell/Trap subtype to Carder semantic `subFamily = NORMAL`.

The Carder type/ability renderer currently decides whether to draw a subtype icon using
the generic condition:

`subFamily !== NO_ICON && size === 'large'`.

For a non-monster Spell/Trap type line this causes the circular NORMAL icon to render even
though NORMAL Spell/Trap has no subtype icon.

The same baseline also uses `sub_family` as a real write-back semantic field:

- server authoritative write projection represents Canonical NORMAL as `NORMAL`;
- explicit `NO ICON` write-back maps to Canonical subtype null;
- explicit supported subtype changes map back to their Canonical subtype codes.

Therefore a naive Workspace adapter change from `NORMAL` to `NO ICON` would risk
changing write-back semantics, including false STRUCTURE differences or
`NORMAL → null`.

### Frozen design decision

The normative requirement is **no rendered NORMAL subtype icon**, not a forced internal
transport-value rewrite.

The preferred bounded correction is therefore renderer-level icon suppression for
non-monster NORMAL Spell/Trap while retaining the existing `NORMAL` semantic token through
Workspace/Carder write projection.

Development may use an equivalent implementation only if it remains within the authorized
technical boundary and proves every acceptance criterion below.

Do NOT remap Canonical NORMAL to `NO ICON` in the Workspace adapter or server authoritative
write projection as a shortcut.

If Development determines that the correction cannot be implemented without changing the
write-back contract or broader bridge/session semantics, STOP and return
`IMPLEMENTATION BLOCKED` to DESIGN_QA with evidence. Do not widen scope unilaterally.
