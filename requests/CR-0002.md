# CR-0002 — Library Dark Theme

## Owner request

Provide a user-selectable dark visual theme for the YU3DOH Workspace Library.

Minimum owner intent:

- the Library can be changed from its current presentation to a dark theme;
- the capability is user-facing rather than a developer-only styling switch.

No broader product behavior is inferred from the request.

## Current disposition

`ACKNOWLEDGED / SCOPE REVIEW REQUIRED`

This request is NOT part of RUN 024.

It is NOT automatically part of Tranche 2 / CR-0001.4.

No implementation branch or RUN is authorized.

## Scope questions

SCOPE_ARCHITECTURE must determine and freeze:

1. exact surface boundary:
   - Library only as the minimum requested capability;
   - whether any shared Workspace shell/theming foundation is technically necessary;
   - Carder is not implicitly included;
2. theme states:
   - required LIGHT/DARK behavior;
   - whether SYSTEM/AUTO is useful or unnecessary;
3. preference lifetime:
   - session-only;
   - browser-local;
   - or another non-domain mechanism;
   - Workspace/database persistence is not presumed;
4. visual coverage:
   - browse/results;
   - Detail/drawers/modals;
   - editor;
   - Variants / Assets;
   - Open in Carder controls;
   - filters, tables, alerts, tooltips/popovers and empty/error states where applicable;
5. accessibility:
   - readable contrast;
   - visible focus;
   - disabled/selected/warning/error state distinguishability;
6. architecture:
   - avoid duplicative one-off styling if a bounded theme-token approach is more appropriate;
   - identify any dependency on current Ant Design/Vite/client styling;
   - determine whether implementation can remain client/UI only;
7. sequencing:
   - assess whether CR-0002 should be bundled with CR-0001.4 / F-04 Library Grid/List because both affect Library presentation;
   - or isolated to reduce regression surface.
